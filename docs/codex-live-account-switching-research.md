# Codex account switching in active CLI sessions

Research date: 2026-10-02.

Several MIT projects manage Codex accounts, but they solve different problems. The reviewed projects do not demonstrate replacement credentials injected into an arbitrary, already running stock Codex session. Some change credentials for future launches. Others restart a process or route model requests through a proxy configured before launch.

This review used public repository documentation, licenses, source code, and existing test definitions. None of the reviewed account-switching tools were installed or executed. Reading a project's tests establishes intended coverage, not that its current release passes them. AIU's subsequent native Codex validation used synthetic credentials, as described below.

## Relevant MIT implementations

- **codex-lb preserves the client through proxy routing.** Its [MIT license](https://github.com/Soju06/codex-lb/blob/main/LICENSE) permits reuse. Its [Codex configuration](https://github.com/Soju06/codex-lb#client-setup) points the CLI at a local Responses endpoint with WebSocket support. The proxy [replaces Authorization and ChatGPT-Account-ID](https://github.com/Soju06/codex-lb/blob/main/app/core/clients/proxy.py#L1018) with selected account credentials. It [selects accounts during streaming retries](https://github.com/Soju06/codex-lb/blob/main/app/modules/proxy/_service/streaming/retry.py#L1421). Existing tests cover [WebSocket reconnection after account failure](https://github.com/Soju06/codex-lb/blob/main/tests/integration/test_proxy_websocket_responses.py#L9685) and [transparent usage-limit retry](https://github.com/Soju06/codex-lb/blob/main/tests/integration/test_proxy_websocket_responses.py#L9858). Continuations, stored objects, and files can belong to a particular account. The code preserves that ownership until safe replay permits movement; an [owner-anchored test](https://github.com/Soju06/codex-lb/blob/main/tests/integration/test_proxy_websocket_responses.py#L10373) returns an unavailable-owner error instead of switching. This is a gateway for Codex clients, rather than a small standalone account-switching CLI.

- **ai-acct-autopilot restarts and resumes the conversation.** The project is [MIT](https://github.com/alnimra/ai-acct-autopilot/blob/main/LICENSE). Its [supervisor](https://github.com/alnimra/ai-acct-autopilot/blob/main/bin/ai-acct-autopilot.js#L1050) launches Codex, then relaunches with `resume <session-id>` after an account change. Its [restart function](https://github.com/alnimra/ai-acct-autopilot/blob/main/bin/ai-acct-autopilot.js#L1126) records session IDs and sends SIGTERM. Sessions started before supervision require manual restart. The reviewed implementation and documentation contain no daemon restart or `--no-daemon` handling. Compatibility with Codex 0.160's shared daemon is unverified; restarting only the terminal client may reconnect to cached daemon credentials.

- **codex-switch handles the shared daemon explicitly.** The project is [MIT](https://github.com/xjoker/codex-switch/blob/master/LICENSE). After changing credentials, its [profile command](https://github.com/xjoker/codex-switch/blob/master/src/commands/profile.rs#L11) calls [restart_daemon_if_live_auth_changed](https://github.com/xjoker/codex-switch/blob/master/src/app_server.rs#L78). It compares parsed authentication, probes daemon status, and runs `codex app-server daemon restart` when needed. Configuration can disable this through `use.restart_app_server=false`. Its [README](https://github.com/xjoker/codex-switch) also discusses `--no-daemon` for stock Codex 0.157 and later. Restarting the daemon interrupts attached sessions; this does not establish uninterrupted in-process switching.

- **Clausona changes the profile for the next launch.** Its [MIT license](https://github.com/larcane97/clausona/blob/main/LICENSE) and [implementation explanation](https://github.com/larcane97/clausona#how-it-works) are explicit: selection updates a profile record, and a shell wrapper supplies that profile's `CODEX_HOME` when launching unmodified Codex. It does not update an existing process.

- **codex-account-switcher swaps the authentication file.** The project is [MIT](https://github.com/Sls0n/codex-account-switcher/blob/main/LICENSE). Its [README](https://github.com/Sls0n/codex-account-switcher) describes switching a symlink or copying a saved account file into the active location. That addresses persisted credentials without a mechanism to replace credentials already cached inside Codex.

- **herdr-account-switch's live-switch claim exceeds its demonstrated mechanism.** Its [license is MIT](https://github.com/rcosteira79/herdr-account-switch/blob/main/LICENSE), and its [README](https://github.com/rcosteira79/herdr-account-switch#what-it-does) claims both CLIs reread authentication for each request. However, [CodexBackend.write_live](https://github.com/rcosteira79/herdr-account-switch/blob/main/switcher.py#L530) only writes `auth.json`; the switch command calls that method without an app-server request or process signal. That source does not demonstrate compatibility with modern Codex's cached authentication.

- **codex-auth requires a runtime change for live switching.** Its [license is MIT](https://github.com/loongphy/codex-auth/blob/main/LICENSE), but its [README](https://github.com/loongphy/codex-auth) says stock CLI and app sessions require restart. It recommends the codext fork for authentication-file watching. [codext is Apache-2.0](https://github.com/loongphy/codext/blob/main/LICENSE), so that combination is not an all-MIT implementation.

## Implications for AIU

The available approaches are a proxy configured before Codex starts, a client connected to the experimental app-server authentication API, or supervised restart/resume with explicit daemon handling. The reviewed MIT tools demonstrate the proxy and restart approaches. None establishes that AIU can hot-inject credentials into an arbitrary existing stock session.

License checks also exclude [codextra](https://github.com/gabewillen/codextra), which declares no license, and the [Apache-2.0 runtime patcher](https://github.com/minanagehsalalma/codex-multiaccount-patcher/blob/main/LICENSE). Their implementation ideas should not be described as MIT code available for reuse.

## AIU implementation validation

AIU now saves the selected credentials, probes daemon status, and restarts a running daemon. Repeated selection of the saved account skips the restart. Failed daemon operations preserve the saved credentials and surface the outcome through the CLI, frontend contract, and Mac app.

Validated on macOS with installed Codex 0.160.0, temporary `CODEX_HOME` and AIU stores, synthetic accounts, and mock workspace and token-refresh endpoints. A native terminal connected to the daemon over its Unix socket stayed in the same process, retained its session ID and unsent draft, and showed the newly selected account's plan after reconnecting. A separate app-server client confirmed the new account email, and the mock backend received its account ID header. Repeated selection kept the existing connection open. Test daemons and temporary credentials were removed afterward; no real provider credentials were used.

Automated checks passed: `go test -race ./...`, `go vet ./...`, Go/Swift switch-result contract fixtures, the signed Mac app build, and Windows cross-compilation. Regression tests cover credential-save ordering, unchanged selections, stopped or older daemons, invalid status responses, failed and cancelled restarts, and failed credential writes.
