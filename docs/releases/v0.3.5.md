AIU 0.3.5 fixes Codex account switches that could leave Codex refusing new sessions with "Server is draining; retry after reconnecting".

AIU 0.3.4 stopped waiting for `codex app-server daemon restart` after 30 seconds. When turns were still running, Codex was still waiting for them to finish, so stopping the restart command left the daemon draining with nothing to replace it, until someone restarted it by hand. AIU now lets a restart that has started run to completion. If the daemon is still finishing turns after about 10 seconds, AIU restarts it again, which stops those turns and starts a replacement. Connected terminals reconnect and reload their saved conversations; re-send any turn that was interrupted.

AIU now confirms that a new daemon process replaced the old one instead of trusting the restart command's exit status. If a restart still does not complete, AIU keeps the saved login, explains that running `codex app-server daemon restart` again forces a stuck daemon to stop, and retries the restart the next time you select that account. If the daemon was already replaced in the meantime, for example by a manual restart, it is not restarted again.

Ctrl-C no longer interrupts a daemon restart that has started. The first Ctrl-C explains that the restart continues; a second exits AIU while the restart completes. The CLI prints restart progress, and the Mac app shows a switching notice and disables switching until the switch finishes. Each daemon step is logged, without command output or credentials, to `codex-daemon.log` in AIU's config directory.

The Codex desktop app and `codex exec` run their own app servers and keep the previous account until they restart. Standalone sessions (`--no-daemon`) still need to exit and resume manually.

Automated tests cover graceful and forced restarts, hung and failed attempts, unverifiable restart output, caller cancellation, process-group isolation, retry and replaced-daemon detection, and log redaction. The fix has not yet been exercised end to end against a real Codex account switch with turns running.

The Homebrew bottle is signed with Parable's Developer ID Application certificate. It is not notarized; source builds may use an ad hoc signature when that certificate is unavailable.
