AIU 0.3.6 adds browser relinking for tracked Claude and Codex accounts whose stored credentials have expired or fallen out of sync.

Choose "Relink with Browser" from an account's menu. Accounts that need sign-in also show a relink button on their card. AIU opens the existing browser authorization flow, shows which account is being relinked, and offers Cancel and Copy Link. Use the account's current browser session, or copy the link into a private window if another account opens. The panel returns to Usage after a successful sign-in and fetches current stats.

Relinking replaces the selected account's credentials and preserves its label. AIU checks the authorized email and organization or ChatGPT account ID before saving. A different account is rejected without changing tracked accounts. An account removed while authorization is pending is not recreated. Closing the sign-in pane cancels the pending login, and output from an earlier login cannot affect a later attempt.

The CLI supports `aiu login claude:work` and `aiu login codex:work` for tracked labels. The JSONL frontend's `login` command also accepts an optional full account selector. Login without a selector continues to add or update the authorized account.

Automated tests cover both providers, successful credential replacement, label preservation, fresh usage after a cached login failure, missing credentials, wrong-account and wrong-organization rejection, removal during login, and frontend cancellation. Live provider authorization still requires the user to finish sign-in in their browser.

The Homebrew bottle is signed with Parable's Developer ID Application certificate. It is not notarized; source builds may use an ad hoc signature when that certificate is unavailable.
